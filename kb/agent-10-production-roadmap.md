# Agent 开发 10：从学习项目到可交付应用

整理日期：2026-09-15。以下路线是为 Java 学习项目设计的实践建议，不是特定厂商的固定产品要求。

## 第一阶段：先做可验证的只读能力
建议从“查笔记并附原文依据”开始，写明输入、预期文档、可接受答案和资料不足时的行为。建立普通问答与流式接口，让页面能显示错误与引用。用本地替身验证业务编排，再用少量真实模型调用验证接入。不要把 mock 测试通过解释成模型不会幻觉。

## 第二阶段：把工具执行做可靠
建议为每个工具建立参数校验、授权、超时和结果结构。写操作增加稳定的幂等标识；运行器设置任务总预算。将发送消息、删除数据等动作与只读查询区分开。先通过故障注入测试，再增加可用工具数量。

## 第三阶段：增加状态与恢复
建议将运行状态保存在持久层，把会话历史、长期偏好和任务检查点分开。网络断开不应让用户完全失去任务状态；提供 runId 查询入口。取消操作要传播到可取消的任务，并明确哪些外部副作用已经发生。恢复时应检查依赖版本和已有结果，避免把旧状态错误地当成新任务。

## 第四阶段：部署和发布
建议让应用使用专用系统用户，在反向代理后运行，密钥来自受限配置而非源码。开发、验证和生产数据库分开；升级前备份并验证恢复方式。知识库文档或 embedding 模型变化时，要说明哪些向量需要重新生成。已有长期数据的系统不能只回滚 jar 而忽略数据库兼容性。

## 一个四周练习安排
第一周完成文档入库、检索和引用；第二周实现两个只读工具及参数校验；第三周加入状态持久化、超时、幂等和人工审批模拟；第四周建立评测集、故障恢复演练和部署说明。每周交付可以演示、可以重复验证的结果，练习进度可按自己的基础调整。

## 项目答辩应该准备什么
建议展示一条成功任务轨迹、一条失败恢复轨迹、一条合理拒答，以及改动前后的同口径评测。清楚区分已经实现、只做了模拟和未来计划。对于“为什么使用多 Agent”“为什么不用更简单的工作流”，用自己的对照结果回答，比列出框架名称更有说服力。
