# Redis 缓存与分布式锁笔记

## 一、缓存穿透、击穿、雪崩

- 缓存穿透：查一个不存在的 key，缓存与数据库都没有 → 请求直达数据库。解决：缓存空值 + 过期时间，或布隆过滤器前置拦截；
- 缓存击穿：某个热点 key 过期瞬间，大量并发同时打到数据库。解决：互斥锁只放一个请求重建缓存，或逻辑过期；
- 缓存雪崩：大量 key 同时过期（或 Redis 宕机），流量直接打崩数据库。解决：过期时间加随机抖动、多级缓存、熔断降级。

## 二、缓存与数据库一致性

先更新数据库，再删缓存（Cache Aside）是工程上常用方案：
- 更新 DB → 删除缓存 → 下次读时回填；
- 若删除缓存失败，可用延迟双删或订阅 binlog 异步补偿；
- 不推荐先更新缓存再写库，容易短暂不一致且难回滚。

## 三、Redis 做分布式锁

分布式锁要求：互斥、防死锁（过期时间）、可重入（可选）、自动续期（可选）。

SET NX EX 是基础形态：
- NX：key 不存在才设置（互斥）；
- EX：过期时间（防死锁）；
- 但业务执行超过过期时间会误删别人的锁 → 用唯一 value（如 UUID）在删除前校验（Lua 脚本保证原子）。

生产方案如 Redisson 提供看门狗自动续期，避免"业务没跑完锁先过期"。

## 四、Redis 数据类型与场景

- String：计数、分布式锁；
- Hash：对象存储（用户信息）；
- List：消息队列、简单延迟任务；
- Set：去重、抽奖、共同好友（交集）；
- ZSet：排行榜、延迟队列（score 为时间戳）。

## 五、持久化与集群（了解）

- RDB：定期全量快照，恢复快但可能丢数据；
- AOF：记录每条写命令，安全但文件大；
- 主从 + 哨兵做高可用；集群模式（Cluster）做分片扩展。
