# Spring AI RAG 实现要点

## 一、RAG 是什么

RAG（Retrieval-Augmented Generation，检索增强生成）是在 LLM 生成前先检索相关资料，把检索结果拼进 Prompt，让模型"基于资料回答"。核心价值是解决大模型的知识时效与幻觉问题，让回答有出处、可追溯。

## 二、RAG 流水线的四个阶段

### 1. 文档解析（Parsing）
把 Markdown、TXT、PDF、Word 等格式的文档解析为纯文本，同时尽可能保留标题结构。标题结构是后续"结构感知切分"的基础。

### 2. 切分（Chunking）
把长文本切成适合向量化的片段。切分质量直接决定检索质量，常见策略：
- 固定长度切分：按字符数硬切，实现简单但容易切断语义；
- 结构感知切分：按 Markdown 标题层级切块，让每个块自带"所属章节"上下文，检索语义更完整；
- 切分参数：块大小（如 800 字符）与相邻块重叠（如 100 字符），重叠能缓解切在语义边界上的损失。

### 3. 向量化与检索（Embedding & Retrieval）
切好的块调用 Embedding 模型（如 text-embedding-v3）转成向量入库。提问时把问题也转成向量，做余弦相似度检索取 top-k。
单靠向量检索的问题：对专有名词、代码、精确术语的匹配不够稳，所以工程上常做"混合检索"——向量检索（语义）+ 关键词检索（BM25，精确匹配）双通道召回后融合排序。

### 4. 生成（Generation）
把检索到的 top-k 块按编号拼进 Prompt，要求模型回答时用 [n] 标注引用来源；检索不达置信度时直接拒答，避免模型硬编。

## 三、混合检索与重排

- 召回阶段：向量通道取 top-20，BM25 通道取 top-20，取并集；
- 融合排序：按权重线性加权（如向量 0.6 + 关键词 0.4），或 RRF 按排名倒数求和；
- 精排：融合后取 top-5 作为最终上下文，控制 token 成本同时保住召回率。

## 四、检索质量怎么量化

不能只靠"感觉变好了"，需要建评测集做消融对比：
- 评测集：从真实知识库文档出题，每题标注"期望命中的文档"；
- 检索侧指标：Recall@5（期望文档出现在前 5 条的比例）、MRR、top-1 命中率，不依赖 LLM、稳定可复现；
- 常见结论：纯向量 vs 纯关键词各有盲区，混合检索的 Recall@5 通常显著高于任一单通道。

## 五、工程注意点

- Embedding 调用要分批（一次别超过 16 条），控制超时；
- 向量入库前做 L2 归一化，之后点积即余弦相似度；
- 无 Docker 的小型知识库可以先自研轻量向量存储（全量余弦扫描，数千块毫秒级），留好接口以后换 Qdrant/FAISS；
- 关键词检索用 Lucene + SmartChineseAnalyzer 处理中文分词。
