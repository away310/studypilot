# Agent 开发 01：架构选择与执行循环

整理日期：2026-09-15。内容是官方概念的学习摘要与本项目练习建议，不代表 StudyPilot 已实现自主 Agent。

## Workflow 与自主 Agent 的区别
固定工作流 Workflow 由代码规定执行路径；自主 Agent 则由模型根据目标、当前状态和工具结果选择下一步。是否使用大模型不是两者的分界线，谁决定运行路径才是关键。固定的解析、检索、生成流程仍是工作流。Anthropic 的架构文章强调从较简单的方案开始，只有效果证据支持时再增加自主性。
来源：[Building effective agents](https://www.anthropic.com/engineering/building-effective-agents)。

## 一个可控的 Agent 循环
建议显式维护 goal、messages、stepCount、remainingBudget、status。每轮先构造上下文，再调用模型。如果模型给出最终答案，校验交付物后结束；如果请求工具，则先校验权限和参数，再执行并追加带调用标识的结果。工具失败应成为下一步可观察的事实，不能被包装成成功。完成判断应根据用户目标和真实结果，不能仅凭模型声称完成。

## 如何防止 Agent 陷入死循环
建议设置最大步数、总时长、模型调用次数和费用预算。预算耗尽应进入明确的终止状态并说明未完成部分。相同工具和参数连续出现、任务状态长期没有变化，是可以记录的无进展信号；阈值要由具体任务确定。工具重试也要消耗同一个总预算，避免内层重试绕过外层限制。

## 选择架构的练习
为学习助手设计三条路径：定义解释使用一次检索问答；生成复习卡片使用固定的提取、生成、格式检查流程；跨多份资料查证冲突才考虑模型驱动的多步检索。先给每条路径写出可检查的成功条件，再比较调用次数、耗时与成功率。自主性是一项可测量的设计选择。

## 最小状态示例
下面是自定义状态示意，不是某框架的固定 API：
```text
RUNNING -> NEED_TOOL -> RUNNING
RUNNING -> WAITING_APPROVAL -> RUNNING
RUNNING -> COMPLETED | FAILED | BUDGET_EXCEEDED
```
练习：让一个虚拟工具连续返回同一个错误，验证系统确实能退出，并保留最后一次错误和已完成步骤。
