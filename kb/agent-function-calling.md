# Agent 与 Function Calling 原理笔记

## 一、什么是 Agent

Agent（智能体）是能"自主规划 + 调用工具 + 完成多步任务"的大模型应用形态。相比单轮问答，Agent 的核心是让模型不再是"一次性回答"，而是可以：
1. 理解用户意图，把任务拆成步骤；
2. 按需调用外部工具（查天气、搜资料、操作数据库）；
3. 根据工具结果继续推理，直到任务完成或需要用户确认。

## 二、Function Calling（函数调用）

Function Calling 是 Agent 调用工具的基础机制。实现上分两步：
1. 把可用工具的"签名"（工具名、参数结构、功能描述）随请求发给模型；
2. 模型判断需要调用某工具时，不直接执行，而是返回结构化 JSON（工具名 + 参数）；
3. 应用侧校验后执行真实函数，把结果作为新的消息回传给模型，模型基于结果继续生成回答。

关键点：
- 工具描述写得越清楚，模型选对工具的准确率越高；
- 参数要定义成严格的 JSON Schema，方便模型结构化输出；
- 同一请求可返回多个工具调用，支持并行执行。

## 三、工具注册表（Tool Registry）

工具多起来后不能硬编码 if-else，需要一个注册中心：
- 每个工具实现统一接口（名称、描述、execute 方法）；
- 启动时自动扫描注册，模型侧看到的"可用工具列表"由注册表动态生成；
- 业务层只依赖注册表接口，不依赖具体工具实现，新增工具不改核心代码。

## 四、多 Agent 与工作流编排

复杂任务可以用"多个 Agent 协作"或"一个 Agent 走多阶段工作流"：
- 角色拆分：规划 Agent、执行 Agent、评审 Agent 各司其职；
- 阶段编排：fetch（取数）→ digest（加工）→ respond（回复），每阶段产出结构化结果传给下一阶段；
- 状态管理：跨阶段共享状态（如 AgentState），支持断点与恢复；
- 失败兜底：单阶段超时或失败时降级，不让整条链路崩溃。

## 五、工程化要点

- 工具调用要做超时控制与失败兜底，模型"决定调工具"后工具挂了不能带崩会话；
- 并行工具执行时注意上下文传递（如租户、用户 ID），避免线程池丢上下文；
- 可观测：把每个阶段、每次工具调用的耗时与 token 记下来，便于排查与成本核算。
