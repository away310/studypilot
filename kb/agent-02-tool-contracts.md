# Agent 开发 02：工具契约、参数校验与幂等

整理日期：2026-09-15。工具契约是应用给模型提供的可调用能力边界。

## 模型请求工具，应用负责执行
工具定义应清楚描述名称、用途、输入参数和返回结果。模型产生调用请求不等于操作已经完成；真正执行工具、检查身份与返回结果的是应用。Spring AI 的工具调用文档明确区分了模型请求与应用执行两个职责。
来源：[Spring AI 1.1 Tool Calling](https://docs.spring.io/spring-ai/reference/1.1/api/tools.html)。

## 工具描述怎么写
官方工具设计文章强调描述、命名、参数和返回信息会影响模型使用工具的效果。建议区分 search_notes 与 delete_note，不要把所有能力藏在一个 execute(action, payload) 接口里。描述应说明使用条件、单位、允许的范围和结果含义；避免把完整数据库表或大段日志原样交给模型。
来源：[Writing effective tools](https://www.anthropic.com/engineering/writing-tools-for-agents)。

## Schema 合法不等于业务合法
JSON Schema 可以约束数据形状，却不能替代应用的授权和业务校验。建议在执行前验证枚举、长度、范围、资源归属和当前用户权限。租户或用户身份应从可信会话注入，不能接受模型声称的 userId。即使参数完全符合 Schema，也可能指向不属于用户的资源。

## 有副作用的工具如何处理重试
工具超时不代表远端操作没有成功。对创建任务、发消息等写操作，建议使用稳定的幂等键和结果查询接口：先查已有执行结果，再决定是否重试；避免每次重试重新生成幂等键。只读查询可以按策略重试，非幂等写操作应先解决结果不确定性。指数退避和抖动是重试调度手段，不能消除重复副作用。

## 结果协议与练习
自定义返回结构可以包含 status、data、errorCode、retryable、requestId。业务错误与网络错误分开记录，让编排器知道是否需要修改参数、请求用户补充信息或稍后重试。练习：模拟“服务端已创建记录，但客户端超时”，验证第二次执行不会产生重复记录。不要向模型返回密钥或完整认证头。
