# MySQL 索引与事务笔记

## 一、索引为什么快

索引是数据库为了加速查询建立的"目录"结构，底层常用 B+ 树。B+ 树的特征：
- 非叶子节点只存索引键，不存数据，单页能容纳更多键 → 树更矮，IO 次数少；
- 叶子节点用链表串联，天然支持范围查询与排序。

建索引的代价：每次写入（增删改）都要维护索引树，索引越多写入越慢；索引还占磁盘。所以索引不是越多越好。

## 二、索引失效的常见场景

- 对索引列使用函数或表达式（如 where YEAR(create_time)=2024）；
- 隐式类型转换（字符串列与数字比较）；
- 左模糊查询 like '%abc'（前缀不确定，无法走索引树）；
- 联合索引不满足最左前缀原则；
- 优化器认为全表扫描比走索引更快（数据量小时常见）。

## 三、事务的 ACID

- Atomicity 原子性：事务要么全部成功要么全部回滚；
- Consistency 一致性：事务前后数据满足约束；
- Isolation 隔离性：并发事务互不干扰；
- Durability 持久性：提交后数据不丢失。

## 四、隔离级别与问题

隔离级别从低到高：
1. 读未提交：可能脏读、不可重复读、幻读；
2. 读已提交（RC）：解决脏读；
3. 可重复读（RR）：解决脏读与不可重复读，MySQL 默认级别；
4. 串行化：全部串行，性能最差。

MySQL InnoDB 在 RR 级别用 MVCC（多版本并发控制）解决快照读的不可重复读，用间隙锁（next-key lock）解决幻读。

## 五、事务与锁实践

- 高并发扣库存、领券等场景，先锁行再更新，或用乐观锁（版本号/CAS）；
- 事务要短平快：长事务持有锁久、undo log 膨胀，拖慢整体；
- 隔离级别选够用就好，不要无脑串行化。
